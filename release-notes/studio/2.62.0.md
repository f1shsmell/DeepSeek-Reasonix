# 2.62.0

本仓库 studio 线的第一个发布版本。代码在上游 v2.61.0（含 2.59 与 2.60 的内容）之上，叠加本仓库分叉后的全部工作：账号中继的推送、附件与授权细分，设备分享的多门与反向代理支持，以及改为运行时自签的发布签名。

> Windows 安装器由每次发布运行时生成并信任的自签证书签名：签名保证的是文件完整性与本次发布的一致性，不是发布者身份，全新安装会显示未知发布者。应用内更新读取的是发布目录中的哈希，不受影响。

## 新增

### 设备分享：多门与反向代理

- 分享不再在多个网络之间二选一：每个网卡地址一扇门，同时监听；关一扇门只停那条入口，其他门与已配对的手机不受影响 (107548e39)
- 配对码按门签发，且只在铸造它的门上兑换：一张局域网二维码被拍照，也不能从公网门兑出去 (4509e71d0)
- `[serve] share_public_origin` 说出反向代理的名字：手机从那里进来，局域网门照旧；反代拨的本机回环门随名字自动开、清名字随之下线，绑定失败的原因回传面板 (327a50611、238122dff、c4f7bbffa)
- 设置页逐地址开关、按需出码；弹卡保留总开关 (045d93667)

### 账号中继：推送、附件与授权

- 内核事件经密封通道内的多路复用流主动推送到手机，轮询成为回退 (b40ce1ce1)
- 附件以二进制密封帧直传，线上体积约省三成 (d2a719170)
- `desktop.request` 隧道内的路径映射到窄 scope：files、terminal 各归其门，desktop 全权兜底 (1691e89d0)

## 变更

- Windows 发布签名改为运行时自签证书 (1e616bf50)
- SignPath 契约收窄到仍到达签名服务的 smoke 工作流 (1e616bf50)

## 修复

- 反代把 Origin 的 authority 一并改写时仍被认作反代，而不是当陌生来源拒绝 (88e041566)
- 未配置中继地址时，设备分享给出"未配置"的答复，而不是指向登录 (f124592ff、18c5f0add)
- https 中继 origin 按手机同样的读法识别 (0f3b5acfd)

## 升级须知

- 设备分享换门要重新扫码：配对码按门签发，凭据按 origin 存放。
- 公开 origin 需要一个 https 反代；TLS 必须在家里那端终结。
- 本仓库的 GitHub Release 是安装包的唯一来源；dl.reasonix.io 的更新目录不属于本仓库，应用内更新器看不到这里的版本，需要手动下载安装。
